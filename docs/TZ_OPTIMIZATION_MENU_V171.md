## 2. Инфраструктура (nginx на 201.51.30.44)

### 2.1. P0 — Кэширование статики (главный тормоз повторных заходов)

**Факт:** `mobile.js?v=171`, `css/*.css`, `assets/**` отдаются **без заголовка `Cache-Control`**. При версионировании через `?v=N` браузер обязан кэшировать их «навсегда», а сейчас каждый визит = повторная загрузка/ревалидация всего.

**Требуется** в `server {}`:

```nginx
# Версионируемая статика — кэш на год, immutable
location ~* \.(?:js|css|woff2?|png|jpe?g|webp|avif|svg|mp4|ico)$ {
    expires 1y;
    add_header Cache-Control "public, immutable";
    access_log off;
}
# HTML и SW — всегда свежие
location = /index.html { add_header Cache-Control "no-cache"; }
location = /sw.js      { add_header Cache-Control "no-cache"; }
```

**Критерий приёмки:** `curl -I .../js/mobile.js?v=171` содержит `Cache-Control: public, immutable`; `index.html` — `no-cache`.

### 2.2. P1 — HTTP/2

**Факт:** сервер отвечает HTTP/1.1. На странице 10+ ассетов (7 CSS + 3 JS) — мультиплексирование HTTP/2 заметно ускорит первый рендер.

```nginx
listen 443 ssl;
http2 on;   # nginx ≥ 1.25.1
```

**Критерий:** `curl -I --http2 .../` → `HTTP/2 200`.

### 2.3. P1 — Security-заголовки

**Факт:** отсутствуют `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`, `Content-Security-Policy`, `Strict-Transport-Security`.

```nginx
add_header X-Content-Type-Options "nosniff" always;
add_header X-Frame-Options "SAMEORIGIN" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
add_header Permissions-Policy "camera=(self), microphone=(), geolocation=()" always;
add_header Strict-Transport-Security "max-age=31536000" always;
# CSP — начать с Report-Only, затем ужесточить:
# add_header Content-Security-Policy "default-src 'self'; img-src 'self' data: https:; media-src 'self' https:; script-src 'self'; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src https://fonts.gstatic.com; frame-src https://rutube.ru https://vk.com https://vkvideo.ru" always;
```
> `camera=(self)` обязателен — иначе сломается видеофиксация в «Герой ГТО». CSP выкатывать через `-Report-Only`, проверив плееры VK/Rutube.

### 2.4. P2 — brotli

Включить `brotli on; brotli_types` для js/css/svg/json — минус ~15–20 % к весу поверх gzip.

## 3. Ассеты (вес)

### 3.1. P0 — Hero-видео

| Файл | Сейчас | Цель |
|---|---|---|
| `assets/video/bg.mp4` (десктоп) | **19,6 МБ** | ≤ 3 МБ |
| `assets/video/bg-mobile.mp4` | 3,2 МБ | ≤ 1,5 МБ |

**Требуется:** пережать (H.264 CRF ~26, `-movflags +faststart`, без аудио), добавить `<video preload="none" poster=…>` и грузить только когда виден. Постер `bg-poster.jpg` (297 КБ) → WebP ≤ 120 КБ.

Команда-ориентир:
```bash
ffmpeg -i bg.mp4 -vf "scale=1600:-2" -c:v libx264 -crf 26 -preset slow -an -movflags +faststart bg.new.mp4
```

### 3.2. P0 — Картинки презентации `assets/pres/*`

**Факт:** `dt-old-home.png` = 3,8 МБ, `dt-home` = 1,5 МБ, `dt-media` = 0,95 МБ и т.д. Весь дек `vozmozhnosti-2026.html` — ~30–40 МБ PNG.

**Требуется:** конвертировать в WebP (качество ~80), ширину десктопных ≤ 1600 px, телефонных ≤ 780 px; в `<img>` проставить `width/height` и `loading="lazy"`. Ожидаемо: весь дек ≤ 6–8 МБ.

## 4. Код

### 4.1. P1 — Ленивая загрузка jsQR

**Факт:** `js/vendor/jsQR.min.js` (56 КБ gzip) подключён `<script defer>` на **каждой** странице, а нужен только в сканере QR («Герой ГТО»).

**Требуется:** убрать тег из `<head>`, грузить через `await import()` в момент открытия сканера. Экономия 56 КБ на каждой загрузке. Аналогично можно `qrcode.min.js` (7 КБ) — по открытию карточки.

## 5. Меню / информационная архитектура

### 5.1. Проблема

Экран **«Ещё» (`data-screen="more"`)** — плоский `link-stack` из ~13 разнородных пунктов подряд:
`Путь атлета` · `Звёзды и амбассадоры` · `База знаний/FAQ` · `О Федерации` · `История` · `Дисциплины` · `Тренировочный таймер` · `Судейские стандарты` · `Руководство` · `Региональные федерации` · `Документы` · `Антидопинг` · контакты.

Три беды:
1. **Нет группировки** — инфо о федерации, инструменты и вовлечение свалены вместе; до нижних пунктов не доскроллят.
2. **Дубли** — «Тренировочный таймер» и «Судейские стандарты» уже есть в быстром доступе на главной и в дровере («Инструменты»). На экране «Ещё» они лишние.
3. **Ценное закопано** — «Путь атлета», «Звёзды и амбассадоры», FAQ (вовлечение новичка) не должны лежать в самом низу служебного экрана.

### 5.2. Решение — сгруппировать экран «Ещё» в 3–4 блока с заголовками

Использовать те же `drawer-section-title`/секции, что уже введены в дровере (единый паттерн). Порядок — по частоте нужд пользователя:

**Блок 1 — «Спортсмену» (вовлечение, наверх):**
- Путь атлета: 5 шагов к разряду
- Звёзды и амбассадоры
- База знаний и FAQ

**Блок 2 — «О Федерации» (справочное):**
- О Федерации · статус, задачи, факты
- История
- Дисциплины · ЕВСК
- Руководство
- Документы · устав, протоколы
- Антидопинг · РУСАДА

**Блок 3 — «Регионы»:**
- Региональные федерации / карта (49 отделений)

**Блок 4 — «Контакты»:**
- Написать в Федерацию · Позвонить

**Убрать с этого экрана** (оставить только в «Инструментах» дровера + быстром доступе главной): Тренировочный таймер, Судейские стандарты.

### 5.3. Требования к реализации

- Каждый блок — заголовок `drawer-section-title` + список карточек `link-stack` (класс уже есть).
- Не плодить новую вёрстку: переиспользовать существующие классы карточек.
- Порядок блоков фиксированный (выше — важнее).
- Семантика: `<nav aria-label="…">` на каждый блок, `<button data-go>` без изменения логики роутинга.
- Дедуп: удалить кнопки `data-go="timer"` и `data-go="standards"` из экрана `more`.

### 5.4. Критерии приёмки

- На экране «Ещё» видны ≥ 3 подписанных блока; первый блок — «Спортсмену».
- Нет пунктов «Тренировочный таймер»/«Судейские стандарты» на экране `more` (они остаются в дровере/на главной).
- Поведение переходов (`data-go`) не изменилось; клавиатурная навигация работает.
