# Техническое задание: оставшиеся улучшения платформы ФМГТО-РФ

**Основание:** повторный аудит production-версии `v166` от 20 сентября 2026 года.  
**Область работ:** только оставшиеся задачи. Уже выполненная очистка календаря, структурирование результатов внутри турнира, группировка медиа и действующая навигация повторно не разрабатываются.  
**Production:** текущий сайт не заменяется до завершения тестирования и подтверждения заказчика.

## 1. Цель

1. Создать работающий самостоятельный раздел «Результаты».
2. Устранить оставшуюся ошибочную дату новости.
3. Ускорить старт приложения и уменьшить обязательный PWA-кеш.
4. Добавить порционную загрузку календаря и новостей.
5. Упростить десктопную шапку.
6. Унифицировать иконки и клавиатурное управление.
7. Сделать выпуск новых версий устойчивым к старому кешу.

## 3. Раздел «Результаты»

### 3.1. Причина текущей ошибки

Кнопка шапки содержит одновременно:

```html
data-go="results"
data-event-all-results
```

Общий обработчик `[data-go]` выполняется раньше специального обработчика. Он вызывает `go('results')`, однако:

- экрана `data-screen="results"` нет;
- маршрут `results` отсутствует среди допустимых экранов;
- функция `go()` заменяет неизвестный маршрут на `home`;
- специальный обработчик результатов становится недостижимым.

### 3.2. Требуемая архитектура

Добавить самостоятельный экран:

```html
<section class="screen" data-screen="results">
```

Добавить `results`:

- в список допустимых маршрутов;
- в обработку начального hash;
- в `popstate`;
- в определение активного пункта десктопного меню;
- в логику кнопки «Назад»;
- в восстановление прокрутки и фильтров.

Прямая ссылка:

```text
#results
```

должна сразу открывать раздел после холодного запуска и после обновления страницы.

### 3.3. Содержимое раздела

Заголовок:

```text
Результаты соревнований
Официальные протоколы турниров Федерации
```

Показывать только турниры, для которых реально найден протокол в `resultsManifest` или подтверждённый официальный документ результатов.

Карточка турнира содержит:

- название;
- дату;
- город и регион;
- количество строк протокола, если известно;
- доступные виды зачёта;
- пометки «личный», «командный», «М», «Ж» только при наличии соответствующих данных;
- дату обновления;
- кнопку «Открыть результаты»;
- ссылку на официальный PDF, если он существует.

### 3.4. Сортировка

По умолчанию:

1. Самые новые завершённые турниры.
2. Более старые турниры по убыванию даты.
3. Турниры без нормализованной даты — в конце.

Будущие турниры без опубликованного протокола в раздел не попадают.

### 3.5. Фильтры

Обязательные фильтры:

- поиск по турниру, городу и участнику;
- год;
- регион или город;
- личный/командный зачёт;
- мужчины/женщины;
- возрастная группа;
- категория;
- комплекс или дисциплина.

Фильтры, которые требуют загрузки конкретного протокола, могут применяться после открытия турнира. На общем экране необходимо явно разделить фильтры каталога и фильтры протокола.

### 3.6. Переходы

- Нажатие «Результаты» в десктопной шапке открывает `#results`.
- Переход назад возвращает предыдущий экран и позицию прокрутки.
- Нажатие на карточку открывает `#event/{id}/results`.
- Если протокол отсутствует или повреждён, показывается сообщение с кнопкой повторной загрузки, а не пустой экран.
- Кнопка «Протоколы» в календаре продолжает вести непосредственно в результаты выбранного турнира.

### 3.7. Мобильная навигация

Нижнее меню остаётся не более чем из пяти пунктов. Отдельный пункт «Результаты» добавлять необязательно, если он вытеснит более важный верхнеуровневый раздел.

Доступ к каталогу результатов обеспечить:

- из экрана «Старты»;
- из поиска атлетов;
- из меню «Ещё/Сервисы»;
- через прямую ссылку `#results`.

### 3.8. Исправление обработчиков

Не использовать два конкурирующих обработчика одной кнопки.

Допустимые варианты:

1. Удалить `data-event-all-results` и использовать только `data-go="results"` с реальным экраном.
2. Либо обрабатывать специальное действие до общего `[data-go]`, но этот вариант допускается только как временный hotfix.

Предпочтителен первый вариант.

## 4. Нормализация новости с датой 1970 года

Исправить запись:

```text
ID: 8
«Агромногоборье для школьников и студентов в Белгородской области»
Текущая дата: «02 мая - 01 января 1970 года»
```

Требования:

- получить реальную дату из официального первоисточника;
- если дата публикации недоступна, хранить `null`, а не 1970 год;
- не выводить вымышленное окончание периода;
- применить общий валидатор дат ко всем новостям, анонсам и отчётам;
- импорт должен завершаться предупреждением при любой дате до 2000 года, если она не подтверждена белым списком исторических материалов.

Критерий приёмки: поиск `1970` по пользовательским данным и интерфейсу не возвращает результатов.

## 5. Порционная загрузка календаря

Сейчас 114 карточек создаются одним вызовом `items.map()`.

Требования:

- первоначально отображать 20 карточек;
- кнопка «Показать ещё» добавляет следующие 20;
- количество оставшихся записей указывается на кнопке;
- при изменении фильтра лимит сбрасывается до 20;
- при возврате из турнира восстанавливаются лимит, фильтры и позиция прокрутки;
- поиск работает по всему массиву, а не только по отображённым карточкам;
- первые карточки сохраняют существующую сортировку: регистрация, будущие, прошедшие;
- после добавления карточек фокус пользователя не переносится принудительно.

Допускается автоматическая подгрузка через `IntersectionObserver`, но должна оставаться кнопка или иной клавиатурно доступный способ загрузить следующую порцию.

## 6. Порционная загрузка новостей

Сейчас все 106 новостей добавляются в DOM сразу.

Требования:

- первоначально отображать 20 новостей;
- следующая порция — 20;
- добавить фильтр по году;
- добавить фильтр по типу: новость, анонс, отчёт, официальный материал;
- поиск выполнять с debounce 200 мс;
- при возврате из публикации сохранять фильтры, лимит и прокрутку;
- сортировать по нормализованной дате публикации от новых к старым;
- публикации без точной даты помещать после датированных материалов соответствующего года.

## 7. Оптимизация JavaScript и данных

### 7.1. Текущее состояние

Стартовый граф статических импортов составляет около 4,61 МБ без административного модуля, камеры, CSS и фонового видео.

Основные тяжёлые ресурсы:

- `vk_albums_data.js` — около 2,30 МБ;
- `gto_data.js` — около 1,25 МБ;
- `mobile.js` — около 487 КБ;
- `herogto_module.js` — около 369 КБ;
- `admin_module.js` — около 490 КБ;
- `bg-mobile.mp4` — около 3,26 МБ.

### 7.2. Требуемое разделение

Разделить `gto_data.js` как минимум на:

```text
calendar-data
news-data
records-data
federations-data
```

Загружать по запросу:

- `vk_albums_data.js` — при открытии медиа или фото турнира;
- `herogto_module.js` — при открытии «Герой ГТО»;
- `admin_module.js` — при открытии панели управления;
- камеру — при открытии записи видео;
- карту и данные регионов — при открытии регионов;
- полный протокол — при открытии результатов конкретного турнира.

Главная страница не должна зависеть от полной базы альбомов, админки, камеры или всех протоколов.

### 7.3. Целевые показатели

На первом открытии Fast 4G:

- первоначальный JS в сжатом виде — не более 500 КБ;
- первоначальные JSON-данные — не более 300 КБ;
- LCP — до 2,5 секунды;
- INP — до 200 мс;
- CLS — до 0,1;
- реакция на нажатие — до 100 мс.

Измерение выполняется на среднем Android-устройстве и отдельно на десктопе.

- полную базу данных сайта;
- фоновое MP4;

### 8.2. Версионирование

Запрещено изменять содержимое уже опубликованного URL `?v=166`.

Предпочтительный формат:

```text
mobile.8f12c39a.js
calendar.31d09a7c.js
styles.715ed821.css
```

Если сохраняется ручная версия, любое изменение любого кешируемого файла требует нового номера во всех ссылках и `CACHE_NAME`.

### 8.3. Обновление

- новая версия устанавливается в отдельный кеш;
- активация не создаёт цикл перезагрузки;
- старая версия удаляется после успешной активации новой;
- пользователь не должен вручную очищать данные сайта;
- при ошибке загрузки новой версии продолжает работать предыдущая;
- показывается компактное уведомление «Доступно обновление» с одной понятной кнопкой.

## 9. Автоматическая проверка выпуска

Перед публикацией:

- синтаксическая проверка всех JS-модулей;
- проверка существования всех импортируемых файлов;
- проверка отсутствия 404;
- проверка manifest и Service Worker;
- проверка данных на 1970 год и обратные диапазоны;
- проверка размера стартового пакета.

После публикации в чистом браузерном профиле:

1. Открыть главную.
2. Проверить отсутствие ошибок консоли.
3. Открыть «Соревнования».
4. Открыть «Результаты».
5. Открыть «Рекорды» и «Медиа».
6. Открыть турнир и вкладки результатов, фото и видео.
7. Проверить прямую ссылку `#results`.
8. Проверить обновление со старой версией Service Worker.

Деплой считается неуспешным при любой необработанной ошибке консоли или неработающем основном маршруте.

## 10. Десктопная навигация

Сейчас выпадающее меню «Сервисы» дублируется постоянной второй строкой сервисов.

Требования:

- оставить выпадающее меню «Сервисы»;
- убрать постоянную вторую строку;
- сохранить доступность всех её пунктов через dropdown;
- добавить WOD-таймер и судейские стандарты в dropdown, если они отсутствуют;
- `aria-expanded` отражает состояние меню;
- Escape закрывает меню;
- после закрытия фокус возвращается на кнопку «Сервисы»;
- клик вне меню закрывает его;
- активный раздел выделяется без изменения размеров элементов.

## 11. Иконки

Заменить структурные эмодзи на единый SVG-набор:

- сервисы;
- форматы турниров;
- регистрация;
- протоколы;
- фото;
- видео;
- карта;
- калькулятор;
- админка.

Требования:

- единая толщина линии;
- размеры через токены: 16, 20, 24 и 32 px;
- декоративные SVG имеют `aria-hidden="true"`;
- кнопка получает доступное имя из текста или `aria-label`;
- цвет задаётся через `currentColor`;
- иконка не является единственным индикатором статуса.

Эмодзи разрешены в редакционных текстах и названиях проектов, но не как системные элементы управления.

## 12. Клавиатурное управление карточками

Основная часть карточки турнира сейчас использует `<div role="button" tabindex="0">`.

Требования:

- заменить её на нативный `<button>` или `<a>`;
- Enter и Space открывают обзор;
- Tab последовательно проходит «Обзор», «Регистрация», «Протоколы», «Фото», «Видео»;
- фокус имеет заметную обводку контрастностью не ниже 3:1;
- вложенные кнопки не запускают действие родительской области;
- после возврата фокус восстанавливается на карточке, из которой был выполнен переход.

## 13. Техническая полировка

- Удалить повторное подключение одной и той же таблицы Google Fonts.
- Перенести повторяющиеся inline-стили в классы и дизайн-токены.
- Не менять inline-стили, которые формируются из реальных динамических значений и не повторяются.

## 15. Критерии приёмки

1. Кнопка «Результаты» открывает самостоятельный экран, а не главную или календарь.
2. `#results` работает после прямого открытия и обновления страницы.
3. Каталог содержит только турниры с реальными протоколами.
4. Карточка каталога открывает `#event/{id}/results`.
5. В пользовательских данных нет 1970 года.
6. Календарь первоначально создаёт не более 20 карточек.
7. Новости первоначально создают не более 20 карточек.
8. Фильтры и прокрутка восстанавливаются после возврата.
9. Фотоархив, админка, камера и «Герой ГТО» не загружаются на главной.
10. MP4 и многомегабайтные каталоги отсутствуют в обязательном кеше установки.
11. Изменённые файлы никогда не публикуются под уже использованным immutable-URL.
12. Выпадающее меню «Сервисы» не дублируется второй строкой.
13. Структурные иконки выполнены в одном SVG-стиле.
14. Карточки и действия управляются клавиатурой.
15. Автоматический smoke-тест проходит без ошибок консоли.
16. Текущая production-версия остаётся доступной до письменного подтверждения новой сборки.
