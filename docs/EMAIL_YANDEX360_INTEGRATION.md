## 1. Что умеет Яндекс 360 для бизнеса и что это значит для сайта

| Возможность | Состояние | Значение для платформы ГТО |
|---|---|---|
| Ящики на своём домене (`info@gto.com.ru`) | Есть | Уже используется как контакт федерации на сайте |
| Отправка писем с сервера | Только **SMTP** `smtp.yandex.ru:465` (SSL) или `:587` (STARTTLS) | Реализовано в `web/server/mailer.js` |
| API отправки писем | **Нет**. API 360 (`api360.yandex.net`) — только администрирование: сотрудники, домены, DNS, DKIM, антиспам, аудит | Для писем используем SMTP; API можно использовать для автозаведения ящиков судьям/регионам |
| Приём писем на сайт (webhook) | **Нет**. Только IMAP `imap.yandex.ru:993` (опрос) | Входящие обращения удобнее принимать формой сайта → письмо в `info@` (сделано: `POST /api/contact`) |
| Лимит отправки с одного ящика | **300 писем (получателей) в сутки** через SMTP, независимо от тарифа. Превышение — блок отправки на 24 ч | Достаточно для подтверждений заявок и вердиктов судей. Для массовых рассылок нужен отдельный сервис (см. 3.3) |
| Авторизация SMTP | Логин — **полный адрес ящика**; пароль — **«пароль приложения»** (обычный пароль не работает; включить в ящике доступ по IMAP; пароль активируется через 2–3 часа). Альтернатива — OAuth XOAUTH2 (`mail:smtp`) | Заводим отдельный ящик `noreply@домен` под сайт, чтобы не сжигать лимит `info@` |
| Бесплатный тариф | **Закрыт с 24.11.2025** (кроме НКО и благотворительных организаций). Организации без тарифа переводятся в «режим просмотра» — отправлять письма нельзя | Если федерация зарегистрирована как НКО — можно запросить бесплатное обслуживание; иначе нужен платный тариф |

### DNS-записи домена для Яндекс 360

| Запись | Хост | Значение |
|---|---|---|
| MX | `@` | `mx.yandex.net.` приоритет 10 (остальные MX удалить) |
| TXT (SPF) | `@` | `v=spf1 redirect=_spf.yandex.net` (если сервер сайта тоже шлёт письма сам: `v=spf1 ip4:201.51.30.44 include:_spf.yandex.net ~all`) |
| TXT (DKIM) | `mail._domainkey` | `v=DKIM1; k=rsa; t=s; p=<ключ из Админки → Домены → Настроить DKIM>` |
| TXT (DMARC) | `_dmarc` | `v=DMARC1; p=none; rua=mailto:info@gto.com.ru` (после месяца наблюдения — `p=quarantine`) |

Проверка: Админка → Домены → «Проверить домен». Распространение DNS — до 72 часов.

## 2. Что сделано в коде сайта

Сайт раньше **не отправлял писем вообще**: заявка на турнир сохранялась только в `localStorage` браузера участника
с случайным номером, федерация о ней не узнавала; кнопка «Связаться» — обычная `mailto:`-ссылка; вердикт судьи в
«Герой ГТО» атлету никак не сообщался.

Добавлено (без внешних npm-зависимостей, в стиле существующего сервера):

| Файл | Что |
|---|---|
| `web/server/mailer.js` (+ копия `web/mailer.js`) | SMTP-клиент на `tls`/`net`: EHLO → STARTTLS/SSL → AUTH PLAIN/LOGIN → DATA; MIME с кириллицей (RFC 2047, base64, multipart/alternative); журнал `data/mail_log.json`; суточный предохранитель `MAIL_DAILY_LIMIT` (по умолчанию 280 < 300 Яндекса); dry-run пока не включено; шаблоны писем |
| `web/api_server.js` (+ `web/server/api_server.js`) | `POST /api/applications` — заявка сохраняется в `data/applications.json`, участнику уходит подтверждение, федерации (`MAIL_ADMIN`) — уведомление с Reply-To на участника; `GET /api/applications` — список для админки; `POST /api/contact` — форма обращения → письмо федерации (honeypot + лимит 10 запросов/10 мин с IP); `GET /api/mail/status` — состояние модуля без секретов; `PATCH /api/hero/videos/:id` — после вердикта `approved`/`rejected` атлету уходит письмо, если в профиле указан email |
| `web/js/app.js` (+ `web/app.js`) | Заявка после локального сохранения отправляется на сервер; номер заявки в окне успеха заменяется серверным; при доставке письма показывается тост |
| `web/js/herogto_module.js` (+ `web/herogto_module.js`) | В загрузку видео добавляется `athlete_email` активного профиля |
| `web/server/.env.example` | Готовые настройки для Яндекс 360, Yandex Cloud Postbox, VK WorkSpace и локального Mailpit |
| `scripts/test_mailer.js` | Тест: фиктивный SMTP-сервер на loopback, проверка диалога, кодировок, шаблонов, dry-run, лимита и обработки ошибок |

Поведение без настроек не меняется: `MAIL_ENABLED` не задан → письма только логируются, ответы API те же.

> Важно: форма заявки в `app.js` не подключена к текущей мобильной сборке — `index.html` загружает только
> `js/mobile.js`, а в нём кнопка «Подать заявку» ведёт на внешнюю страницу регистрации gto.com.ru. Поэтому
> сейчас «живые» письма — это вердикты судей из «Герой ГТО» (модуль загружается из `mobile.js`) и
> `POST /api/contact` / `POST /api/applications`, которые можно вызвать из любой формы. Чтобы заявки с сайта
> приходили на почту, нужно либо добавить в `mobile.js` собственную форму, отправляющую `POST /api/applications`,
> либо подключить `app.js`.

### Включение на проде (Яндекс 360)

1. В админке Яндекс 360 создать сотрудника/ящик `noreply@<домен>` (или использовать `info@`).
2. Под этим ящиком: Почта → Настройки → «Почтовые программы» → включить «С сервера imap.yandex.ru по протоколу IMAP» и «Пароли приложений и OAuth-токены».
3. https://id.yandex.ru/security → «Пароли приложений» → «Почта» → создать, скопировать (показывается один раз; заработает через 2–3 часа).
4. На сервере `201.51.30.44` задать переменные окружения процессу `api_server.js` (пример — `web/server/.env.example`):
   ```
   MAIL_ENABLED=1
   SMTP_HOST=smtp.yandex.ru
   SMTP_PORT=465
   SMTP_USER=noreply@<домен>
   SMTP_PASS=<пароль приложения>
   MAIL_FROM=Федерация многоборья ГТО <noreply@<домен>>
   MAIL_ADMIN=info@gto.com.ru
   ```
5. Перезапустить API и проверить `GET /api/mail/status` → `enabled: true, configured: true`; отправить тестовую заявку; посмотреть `data/mail_log.json`.
6. Убедиться, что в DNS домена есть SPF и DKIM (раздел 1), иначе письма уйдут в спам.

Локальная проверка без интернета: `node scripts/test_mailer.js`.

Экономия против Яндекс 360 «Минимальный» — около 18 000 ₽/год на 5 ящиков и около 37 000 ₽/год на 10.
- Яндекс 360 стоит оставить, если важны Диск/Телемост/Документы для сотрудников или **федерация оформлена как НКО** — тогда Яндекс обслуживает бесплатно, и это лучший вариант из всех.
- Переезд провайдера для сайта — это только смена четырёх переменных `SMTP_*` (см. `.env.example`), код не меняется.

## 4. Рекомендуемая схема

1. **Сейчас**: ящик `noreply@домен` в Яндекс 360 + пароль приложения → включить `MAIL_ENABLED=1`. Уведомления о заявках и вердиктах заработают сразу.
2. **DNS**: проверить SPF/DKIM/DMARC (раздел 1), иначе подтверждения участникам уйдут в спам.
3. **Экономия**: если сервисы Яндекс 360 кроме почты не используются — перевести домен на VK WorkSpace (0 ₽ до 5 ящиков) или Timeweb «Почтовый» (950 ₽/год). Если федерация — НКО, запросить у Яндекса бесплатный тариф.
4. **Рост**: при более 300 писем/сутки — Yandex Cloud Postbox.

## 5. Чек-лист для проверки в admin.yandex.ru (вручную)

- Организация → **Тариф и оплата**: какой тариф активен, дата окончания, число оплаченных сотрудников, нет ли «режима просмотра».
- **Домены**: какой домен подключён, статус «Подтверждён», MX/SPF/DKIM — все зелёные; включён ли DKIM.
- **Сотрудники**: сколько ящиков реально используется (для расчёта тарифа выше).
- **Безопасность → Пароли приложений**: разрешены ли; создать пароль для `noreply@`.
- **Почта → Правила обработки**: нет ли пересылок, которые ломают доставку `info@`.
